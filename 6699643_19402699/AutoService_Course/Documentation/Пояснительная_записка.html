Введение

В работе автосервиса постоянно обрабатываются сведения о клиентах, автомобилях, видах ремонтных работ, запасных частях и заказах. При ведении раздельных таблиц затрудняется поиск истории обращения, возникает риск повторного ввода одной и той же информации, а изменение статуса заказа требует нескольких несвязанных действий. Для учебного проекта целесообразно объединить указанные сведения в настольную информационную систему, основанную на реляционной базе данных.

Объектом исследования является деятельность автосервиса по учёту обращений клиентов и обслуживанию автомобилей. Предмет исследования - методы проектирования и реализации программных модулей настольной информационной системы с хранением данных в Microsoft SQL Server.

Цель курсового проекта - разработать приложение на языке C# с интерфейсом WPF для выполнения основных операций с предоставленной базой данных db_autoservice. Приложение должно позволять просматривать, находить, создавать, изменять и удалять записи; при создании связанных записей пользователь должен выбирать значения из существующих справочников.

Для достижения цели сформулированы следующие задачи: проанализировать структуру переданной базы данных; определить основные сущности и способы их отображения; выбрать средства реализации клиентского интерфейса и доступа к данным; разработать экранные формы; реализовать операции добавления, чтения, изменения и удаления данных; предусмотреть проверку значений; подготовить сценарии тестирования и инструкцию по запуску.

Практическая значимость проекта заключается в создании обозримого настольного приложения для типовых операций приёма автомобилей в ремонт. Реализация ориентирована на учебный масштаб: один клиентский экземпляр, локальный или доступный по сети SQL Server, небольшой объём данных. Вопросы промышленной эксплуатации, разграничения ролей и аудита изменений обозначены как возможные направления развития.

Исходные материалы включали SQL-скрипт базы db_autoservice, две части практического задания по созданию приложения WPF, а также пример структуры пояснительной записки. В учебных материалах рассматривалась предметная область компании с продуктами и материалами. В данном проекте эта схема заменена реальной предметной областью автосервиса, а доступ к данным реализован стандартным ADO.NET.

1 Выбор средств и технологий разработки

1.1 Анализ задачи и функциональные требования

Пользователем системы является сотрудник автосервиса, которому необходимо найти автомобиль или клиента, посмотреть перечень ремонтных заказов, добавить новое обращение и уточнить данные существующей заявки. Основными объектами учёта приняты заказы, автомобили, владельцы, услуги и запчасти. Остальные таблицы используются как справочники при заполнении карточек.

1.2 Обоснование выбора программных средств

Для разработки выбран язык C#, поскольку он предоставляет типизированную модель данных, средства обработки исключений и штатные библиотеки для настольных приложений. Графический интерфейс создан с помощью Windows Presentation Foundation. WPF позволяет декларативно описывать структуру окна на XAML, а работу элементов управления реализовать в связанных файлах C#.

Проект ориентирован на .NET Framework 4.8. Такой вариант совместим с учебными практиками, в которых используется классический проект WPF для Windows. Базой данных служит Microsoft SQL Server. СУБД обеспечивает хранение таблиц, проверку ограничений первичных и внешних ключей и выполнение запросов на выборку, вставку, изменение и удаление.

Для доступа к данным применяется ADO.NET (`System.Data.SqlClient`): объект `SqlConnection` открывает соединение, `SqlCommand` выполняет запрос с параметрами, `SqlDataAdapter` заполняет `DataTable`. Выбор ADO.NET позволяет обойтись без дополнительной установки пакетов NuGet и напрямую использовать уже существующую структуру базы. В примере учебного задания используется Entity Framework 6; для данной небольшой схемы ADO.NET обеспечивает достаточные возможности и оставляет работу с SQL явной.

2 Разработка информационной структуры базы данных

2.1 Анализ исходной схемы

Переданный скрипт базы данных содержит 15 таблиц. Центральным объектом является таблица `Zakaz`, в которой хранятся номер заявки, автомобиль, дата ремонта, статус, причина обращения, пробег, сотрудник, услуга, запчасть и количество. Таблица `Automobiles` связана с владельцами, моделями и техническими справочниками. Нормативная стоимость услуги задаётся в таблице `Work_price`.

Стрелка направлена от справочной таблицы к таблице, содержащей внешний ключ. Упрощённая инфологическая схема.

Рисунок 1 - Основные связи данных автосервиса

Типичная связь «один ко многим» возникает между владельцем и автомобилями: один владелец может быть связан с несколькими автомобилями, при этом у автомобиля хранится одно значение `id_owner`. Аналогичным образом одна услуга из `Work_price` может входить в несколько заказов. Для заказа обязательно указываются автомобиль, статус, причина, сотрудник и услуга, а запчасть допускается не выбирать.

В SQL Server связи закреплены ограничениями `FOREIGN KEY`. При попытке удалить клиента, имеющего автомобили, СУБД должна отклонить действие. В интерфейсе при такой ситуации выводится диагностическое сообщение. Такой подход сохраняет ссылочную целостность и предотвращает появление заказа со ссылкой на несуществующее транспортное средство.

Исходная структура накладывает отдельное ограничение: одна строка `Zakaz` содержит ссылку только на одну услугу и одну запчасть. Для полноценного заказ-наряда с несколькими позициями в дальнейшем потребуются связующие таблицы `OrderServices` и `OrderParts`. В рамках текущего проекта структура не изменялась, чтобы сохранить совместимость с предоставленной базой.

В исходной таблице `Users` присутствует столбец `password` с текстовым типом. В рассматриваемом приложении аутентификация не реализована, значения этого столбца не читаются и не проверяются. Перед реальным применением системы хранение паролей и разграничение доступа необходимо пересмотреть отдельно.

3 Проектирование пользовательского интерфейса

Интерфейс выполнен в виде единого главного окна. Слева находится вертикальная панель навигации с пятью разделами. В центральной части размещены название активного раздела, поле поиска, кнопки управления и таблица данных. 3.2 Диалог добавления и редактирования

Форма редактирования получает описание выбранного раздела и формирует поля ввода. 4 Реализация программных модулей

4.1 Структура решения

Проект оформлен как решение Visual Studio `AutoService.sln`, содержащее классическое WPF-приложение `AutoService.Wpf`. Разметка основного окна хранится в `MainWindow.xaml`, обработчики кнопок и табличного списка - в `MainWindow.xaml.cs`. Диалог универсального редактирования состоит из `EditDialog.xaml` и `EditDialog.xaml.cs`.

В `Data/SqlRepository.cs` сосредоточены операции обращения к базе данных. Благодаря такому разделению интерфейс не содержит SQL-команд, формируемых из текста пользователя.

4.2 Чтение, поиск и обновление записей

При открытии раздела `SqlRepository.Query` выполняет запрос `SELECT` со связями `LEFT JOIN`, возвращая `DataTable`. Представление `DefaultView` назначается в `ItemsSource` компонента `DataGrid`. Колонки создаются по описанию текущей сущности, поэтому после смены раздела обновляются и заголовки, и состав выводимых полей.

Поиск производится по уже загруженному представлению `DataView`. Текст запроса преобразуется в условие `RowFilter` для выбранных колонок. Поиск не удаляет и не изменяет данные в SQL Server. Операция «Обновить» заново загружает строки с сервера, что позволяет увидеть последние сохранённые изменения.

Добавление и обновление сведений реализованы одним методом `Save`. Программа получает описание разрешённых полей из `EntityCatalog`, составляет список параметров и вызывает `SqlCommand`. Значения полей передаются отдельно от SQL-текста, поэтому спецсимволы в фамилии клиента или названии услуги не становятся частью синтаксиса запроса.

Листинг 1 - Принцип передачи параметров при сохранении

for (int i = 0; i < schema.Fields.Length; i++)
{
    var field = schema.Fields[i];
    command.Parameters.AddWithValue(
        "@p" + i, values[field.Column] ?? (object)DBNull.Value);
}
connection.Open();
int affected = command.ExecuteNonQuery();

При изменении записи используется значение `id` выбранной строки. При удалении выполняется команда `DELETE FROM ... WHERE id=@id` с целочисленным параметром. В отсутствие подтверждения от пользователя запрос не отправляется. Если удаляемая запись участвует во внешних ключах, SQL Server возвращает исключение, которое отображается в интерфейсе с пояснением.

4.3 Проверка данных и обработка ошибок

Проверка производится на уровне интерфейса до выполнения запроса. Обязательные строки не могут состоять только из пробелов; для числовых полей используется преобразование `TryParse`; дата выбирается через календарь; для внешних ключей требуется элемент списка. Это предотвращает наиболее распространённые ошибки заполнения форм.

Дополнительные ограничения согласованы с исходной базой. Текстовые поля ограничены 50 символами, поскольку именно такая максимальная длина указана в большинстве столбцов `nvarchar(50)`. Цена не может быть отрицательной, должна быть целой и помещаться в `DECIMAL(6,0)`. Для количества и номера заказа требуется положительное значение. Год выпуска детали ограничен диапазоном от 1900 до следующего календарного года.

При невозможности подключиться к серверу отображается сообщение с рекомендацией проверить `App.config`, имя экземпляра и доступность базы. При ошибке сохранения или удаления показывается текст исключения. Приложение не содержит скрытого режима работы с тестовыми данными: при отсутствии SQL Server списки не подменяются образцами.

Возможность прямого SQL-доступа предполагает доверенную учебную среду и права пользователя Windows, под которыми выполняется приложение. Для промышленной версии рекомендуется выделить отдельную учётную запись БД с минимально необходимыми правами, добавить журнал изменений и ограничить доступ к персональным данным клиентов.

Заключение

В результате разработки подготовлено настольное приложение для учёта данных автосервиса на C# и WPF. Его функциональная модель охватывает пять основных разделов: заказы, автомобили, клиентов, услуги и запчасти. Реализованы обработчики навигации, загрузка таблиц, поиск, универсальная форма добавления и редактирования, удаление с подтверждением и проверка вводимых значений.

При разработке использована предоставленная структура базы `db_autoservice`. Сохранены названия и типы исходных таблиц и полей; для удобства переноса создан отдельный скрипт с относительной к серверу конфигурацией файлов хранения. Приложение использует соединение с MS SQL Server и параметризованные команды ADO.NET.

Курсовой проект демонстрирует разделение интерфейса, описания предметных сущностей и доступа к данным. Следующие этапы развития могут включать полноценные заказ-наряды с несколькими услугами и деталями, авторизацию сотрудников, печать документов, историю изменений и автоматизированные тесты. Для подтверждения работоспособности на конкретном компьютере необходимы сборка проекта на Windows, настройка SQL Server и выполнение проверок по таблице 6.

Приложение Б Порядок установки и запуска

  1. Открыть SQL Server Management Studio и подключиться к локальному экземпляру SQL Server. При использовании LocalDB обычно применяется имя `(localdb)\MSSQLLocalDB`.
  2. Открыть `Database/01_create_database.sql` и выполнить скрипт. Проверить наличие базы `db_autoservice` и таблиц в разделе «Таблицы».
  3. Для демонстрации работы с непустой базой, если данные отсутствуют, выполнить `Database/02_demo_data.sql`. Демонстрационный скрипт не рекомендуется запускать на рабочей БД.
  4. Открыть проект `AutoService.sln` в Visual Studio 2022 с установленной поддержкой .NET Framework 4.8 и WPF.
  5. Проверить `AutoService.Wpf/App.config`. Если экземпляр называется `./SQLEXPRESS` либо содержит иное имя сервера, заменить значение `Data Source`. База должна называться `db_autoservice`.
  6. В обозревателе решений назначить `AutoService.Wpf` запускаемым проектом, выбрать Debug и выполнить «Сборка решения».
  7. Запустить приложение клавишей F5. Проверить пять разделов и кнопки «Добавить», «Изменить», «Удалить», «Обновить».
  8. При ошибке подключения убедиться, что служба SQL Server запущена и текущий пользователь Windows имеет права на базу данных.

В случае использования сервера SQL Server Express вместо LocalDB строка может содержать `Data Source=.\SQLEXPRESS`. Для подключения к удалённому SQL Server требуются настроенный сетевой доступ, корректные права и соответствующий параметр сервера; изменение сетевых правил выполняется администратором.
